4. Calculations

Confirmed tax treatment

RRP is the SKU Price and includes GST. Subtotal must be shown excluding GST, so first convert RRP to an ex-GST unit price.

Ex-GST Unit PriceRRP / 1.10
Line Subtotal (ex GST)Ex-GST Unit Price x Quantity
Order Subtotal (ex GST)Sum of all Line Subtotals for that order
GSTOrder Subtotal x 10%
Order TotalSubtotal + GST + Shipment Fee
CurrencyAUD, displayed to two decimal places
  • Calculate and display results separately for each order.
  • Compute each value from the source data. Do not hard-code calculated totals.
  • Show the RRP, ex-GST unit price, quantity and ex-GST line subtotal for each SKU.

7. Shipment Fee

RequiredYou must consider the shipment-fee calculation process and describe your approach in the README.

BonusA working shipment-fee estimate earns bonus credit. If you do not complete the estimate, display A$0.00 and continue.

Information available for an estimate

  • SKU Weight, Width, Length and Height, or Volume where provided.
  • Origin postcode: 2111 (Ryde, NSW).
  • Destination postcode from the relevant customer's shipping address.

You may use a shipping API or a reasonable formula based on weight and volume. The fee is calculated at order level. You may make and document reasonable design assumptions about how the fee is aggregated or stored.

8. Additional Test Orders and Real-Order Readiness

You may create several additional test orders. Treat any generated test data as a reasonable assumption and document it in the README.

  • Keep the order-processing logic data-driven.
  • Do not hard-code the supplied order numbers, SKU codes, prices or calculated results into the business logic.
  • Ensure the application can process real order data that follows the same documented input structure.
  • Consider testing multiple SKUs, missing SKU matches, invalid quantities and unavailable tracking results.

9. Final Output and Deliverables

Application

  1. A complete front-end application that displays the required order, SKU, calculation and tracking information.
  2. A back-end or supporting service that reads the chosen order-data format, matches SKU data and performs the calculations.
  3. Supplementary console output or a JSON view is acceptable, but it does not replace the required front-end user interface.

Minimum front-end content

  • Order header and shipping information.
  • Each SKU's code, name or description, quantity, RRP, ex-GST unit price and ex-GST line subtotal.
  • A generated or neutral product-image placeholder.
  • Tracking information and a clear API-unavailable state.
  • Subtotal excluding GST, GST, Shipment Fee and Total for each order.

12. Frequently Asked Questions

1. What is the SQL link, and what does RRP mean?

The SQL-like website exposes an extract from one of our data tables. Querying the interface is not being assessed as a separate API-integration task. You may run the required query, copy the returned JSON and use it locally. RRP means Recommended Retail Price. For this assessment, RRP is the SKU Price, is denominated in AUD and includes GST.

2. Do the table names in the SQL examples apply to this assessment?

Not necessarily. The queries shown in the Examples section demonstrate syntax only. Read the page carefully and confirm the correct table name before running your query. Do not assume that a table name used in an example is the table name required for this task.

3. What business context should I use?

All business scenarios are Australian. The product's stakeholders and customers are also based in Australia. Use Australian addresses, postcodes, currency, GST treatment and relevant business conventions.

4. May I make assumptions?

Yes. You may make reasonable assumptions where information is incomplete. Clearly record each material assumption and explain its effect in the README.

5. May I create additional test orders?

Yes. You may generate several test orders as reasonable assumptions. Your application must remain data-driven and should also produce correct results when real orders following the same documented input structure are supplied.

6. How should I test Australia Post tracking?

You may consult the Australia Post developer website to understand the API. The information required for the supplied test environment is included in this brief. The following additional Australia Post / StarTrack numbers are available for testing:

RBXZ50016112 2FWZ50020500 2FWZ50020498 2FWZ50020475

These are additional test numbers, not extra order line items. If an API or test number does not work, describe what you tested and the observed limitation in the README.

7. Is TNT integration mandatory?

No. TNT research and integration is optional bonus work. If it is not implemented, or the API does not work, display the related Shipment Fee as A$0.00, present a clear unavailable or not-implemented tracking state, and document the reason in the README.

8. Do I need real product images?

No. Reserve an image area for each product, but you may use generated placeholders labelled Product 1, Product 2 and so on, or a neutral medicine-bottle icon. Record this assumption in the README.
